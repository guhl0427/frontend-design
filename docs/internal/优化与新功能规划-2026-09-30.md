### 严重问题（建议修复）

#### S1：模态弹窗缺少焦点管理，键盘/读屏用户会被卡住

**位置**：`src/components/PromptDetail.tsx:98-190`  
**问题描述**：弹窗用 `div[role=dialog]` 实现，但缺三件套：

1. **无焦点陷阱**：打开后按 Tab，焦点会跑到弹窗背后的卡片与筛选按钮上（背景可见却不可交互，屏幕阅读器会读到无关内容）
2. **无初始聚焦**：打开后焦点仍停留在触发按钮，键盘用户需 Tab 多次才能进到弹窗
3. **无焦点归还**：关闭后焦点丢失到 `body`，键盘用户需从页首重新 Tab

**影响**：WCAG 2.1 键盘可访问性不达标（焦点顺序失控）；纯键盘用户实际无法顺畅使用详情功能。  
**证伪尝试**：是否存在原生 `<dialog>` 元素或第三方库代为管理？已核对——组件用裸 `div` + 手写 Esc/滚动锁定，无任何原生焦点语义，反例不成立。

**修复建议**（约 25 行，抽成 `useFocusTrap` 或直接写在组件内）：

```tsx
const panelRef = useRef<HTMLDivElement>(null);
const triggerRef = useRef<Element | null>(null);

useEffect(() => {
  triggerRef.current = document.activeElement;
  const panel = panelRef.current;
  if (!panel) return;
  const focusables = panel.querySelectorAll<HTMLElement>(
    'button, [href], input, [tabindex]:not([tabindex="-1"])',
  );
  focusables[0]?.focus();

  const onKeydown = (e: KeyboardEvent): void => {
    if (e.key !== 'Tab') return;
    const list = Array.from(focusables);
    const first = list[0];
    const last = list[list.length - 1];
    if (e.shiftKey && document.activeElement === first) {
      e.preventDefault();
      last.focus();
    } else if (!e.shiftKey && document.activeElement === last) {
      e.preventDefault();
      first.focus();
    }
  };
  document.addEventListener('keydown', onKeydown);
  return () => {
    document.removeEventListener('keydown', onKeydown);
    (triggerRef.current as HTMLElement | null)?.focus();
  };
}, []);
```

并给面板加 `ref={panelRef}`。

### 警告（建议修复）

#### W1：复制逻辑重复两处，且 `setTimeout` 未清理

**位置**：`StyleCard.tsx:16-22`、`PromptDetail.tsx:88-94`  
**问题描述**：两处 `handleCopy` 实现逐字重复；`window.setTimeout(() => setCopied(false), 2000)` 未保存 id、未在卸载时 `clearTimeout`。快速连点「复制」会叠加多个定时器，出现「刚点完就闪回未复制态」的视觉错乱。  
**影响**：行为不一致（连点场景反馈错乱）+ 双份维护成本。  
**修复建议**：抽 `src/hooks/useCopy.ts`：

```ts
export function useCopy(): { copied: boolean; copy: (text: string) => Promise<void> } {
  const [copied, setCopied] = useState(false);
  const timer = useRef<number | null>(null);

  useEffect(() => () => { if (timer.current !== null) window.clearTimeout(timer.current); }, []);

  const copy = useCallback(async (text: string) => {
    if (!(await copyToClipboard(text))) return;
    setCopied(true);
    if (timer.current !== null) window.clearTimeout(timer.current);
    timer.current = window.setTimeout(() => setCopied(false), 2000);
  }, []);

  return { copied, copy };
}
```

两处改为调用该 hook，净减约 12 行。

#### W2：半透明色板值在详情页色块中显示失真

**位置**：`PromptDetail.tsx:148`（`backgroundColor: swatch.value`）+ `src/data/styles.ts`  
**问题描述**：17 处色值使用 `rgba()` 半透明（实测：4 款风格的 `surface`、2 款 `border`、2 款 `textMuted` —— 玻璃拟态、蒸汽波、极光渐变、Fluent 2 等）。色块直接铺在深色卡片上，`rgba(255,255,255,0.55)` 显示成灰、`rgba(41,49,61,0.12)` 几乎不可见——用户看到的不是该颜色本身。  
**影响**：色板可视化对「半透明流派」风格给出错误信息，恰好是这批风格最核心的设计语言。  
**修复建议**：色块底部垫一层固定棋盘格/中灰底（表示 alpha 通道）：

```tsx
<div className="h-10 w-full"
     style={{ backgroundColor: swatch.value,
              backgroundImage: 'repeating-conic-gradient(hsl(0 0% 60%) 0% 25%, hsl(0 0% 30%) 0% 50%)',
              backgroundSize: '10px 10px' }} />
```

#### W3：预览区对屏幕阅读器是纯噪声

**位置**：`StyleCard.tsx:27-35` + `Preview.tsx:147-228`  
**问题描述**：按钮已有 `aria-label`，但其内部 Preview 的十余个文本节点（「立即开始」「了解更多」「色板 字体 圆角」「Archivo Black」…）仍会被逐个朗读，形成一长串无意义播报。  
**修复建议**：给 Preview 根 `div` 加 `aria-hidden="true"`（可视化信息已由按钮 label + 详情页色板承载）。

#### W4：页面状态不进 URL，分享与刷新即丢失

**位置**：`App.tsx:25-27`（三个 `useState`）  
**问题描述**：分类、关键词、当前打开的详情弹窗均为内存态。用户无法把「艺术分类 + 搜索国风」的视图发给别人，刷新回到初始态，浏览器后退键不生效。  
**影响**：作为「提示词画廊」这类工具站，可分享性是核心体验之一（对标项目 OhMySkyles、claude-directory 均支持直达单个风格）。  
**修复建议**：用 `URLSearchParams` 双向同步（无需引入路由库）：  
`?cat=艺术&q=国风&style=guochao` —— 挂载时读取初始化、变更时 `history.replaceState`。

#### W5：全部提示词正文打进主 bundle，风格数增长会线性恶化

**位置**：构建产物  
**证据**：`npm run build` → `index-BSqfU3Oi.js 193.94 kB / gzip 68.22 kB`（25 条风格时）。其中提示词正文约 1.5 万字是纯文本负载。  
**影响**：风格数翻到 100 条时预计主包 > 500 kB / gzip > 150 kB，首屏解析与首图时间同步恶化。当前 25 条尚可接受，属**预防性优化**。  
**修复建议**（两条路径，按需择一）：

- 轻量：`styles.ts` 只保留卡片所需元信息；提示词正文拆到 `src/data/prompts/*.ts`，详情弹窗打开时 `await import()` 动态加载（主包可回落至 ~60 kB）
- 保守：维持现状，待风格数 > 60 条再动（Karpathy：不为想象中的规模付费）

#### W6：无可执行的测试入口，验证能力锁在一次性脚本里

**位置**：`package.json:6-10`（仅 dev/build/preview）  
**问题描述**：QA 三轮与增量验证产生了 11 个脚本（`scripts/*.sh`、`qa-validate.mjs`、`verify-styles.mjs`），但未纳入 `npm scripts`，也无 CI。这些资产目前「人走茶凉」——下次改动无人会自动跑。  
**修复建议**：加两条命令即可闭环，零依赖成本：

```json
"verify:data": "node scripts/verify-styles.mjs",
"verify": "npm run verify:data && npm run build"
```

（Playwright 断言脚本保留在 `scripts/`，作为改动 UI 前的手动回归清单。）

#### W7：缺 favicon 与社交分享元信息

**位置**：`index.html:3-8`  
**问题描述**：① `favicon.ico` 404（QA 三轮一致报告，浏览器标签页与收藏夹为空白图标）；② 无 `og:title/og:description/og:image`、无 `twitter:card`。分享到微信/推特/Slack 时无预览卡片。  
**修复建议**：加一枚 SVG favicon（可复用站点 `brand` 绿 `hsl(160 84% 45%)`）；补 4 条 OG 元信息。若计划上线，一并补 `theme-color` 与 `sitemap.xml`。

### Karpathy 维度评估

**正面（克制得对）**：

- 没有状态管理库、没有路由库、没有组件库、没有后端 —— 三个 `useState` 撑起全部交互，这是正确的判断
- 数据与 UI 分离（`data/styles.ts` 独立），加一款风格只改 1 个文件
- 预览用纯 CSS 实时渲染而非截图/GIF —— 零版权负担且与提示词强一致，是产品级的好决策
- 依赖仅 React + 构建链，无幽灵依赖

**需警惕**：

- `Preview.tsx` 的 switch 分派在变体增长后会变成「改一处动全身」，但**现在重构属于典型的过度设计**——建议等变体数超过 12 个（当前 8 个）再抽象
- 不要为想象中的规模提前拆分数据（W5），先确认风格数是否真会破百

## 四、明确不建议做的（防过度工程）

| 不建议                          | 理由                                            |
| ---------------------------- | --------------------------------------------- |
| 引入 Redux/Zustand             | 全部状态 = 3 个 `useState`，引入状态库是纯负担               |
| 引入 react-router              | `URLSearchParams` 足够撑 F1；纯静态站不需要路由层           |

| 引入 MUI 等组件库                  | Tailwind + 现有组件已足够，且组件库默认风格会污染「画廊展示多样性」这个核心体验 |
| 提前拆分数据文件 / 重构 Preview switch | 当前规模下属于为想象中的需求付费，等触发阈值再动                      |
| 现在就上后端与数据库                   | 除 F11 社区投稿外，所有规划功能都能纯前端完成                     |
