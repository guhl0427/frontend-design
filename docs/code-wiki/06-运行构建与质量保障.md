# 06 · 运行、构建与质量保障

> 三层验证：**类型**（编译器）→ **数据**（`verify:data`）→ **行为**（`verify:ui`，43 项浏览器断言）。三者互不重叠，缺一层就会漏掉一类错误。

---

## 1. 环境要求

| 项 | 要求 | 依据 |
| --- | --- | --- |
| Node.js | `^20.19.0 \|\| >=22.12.0` | `vite@8.3.7` / `@vitejs/plugin-react@6.3.0` 的 `engines` |
| npm | 任意现代版本（实测 10.9.7） | 无 workspace、无 pnpm/yarn 配置 |
| 包管理器 | npm（有 `package-lock.json`） | 换包管理器会生成第二份锁文件，不建议 |
| 浏览器（开发预览） | Chrome 111+ / Safari 16.4+ / Firefox 128+ | Tailwind 4 依赖 `color-mix()`，不支持时所有透明度修饰失效 |
| 浏览器（`verify:ui`） | 本机 `ms-playwright` 缓存中的 Chromium | 脚本写死两个候选路径 |
| 网络 | 仅访问 Google Fonts | 离线也能跑，只是字体回落 |

**实测环境**：Windows 11 + Git Bash + Node 22.22.2 + npm 10.9.7。

## 2. 安装与启动

```bash
# 在仓库根目录（style-gallery/）
npm ci                 # 按 lock 精确安装；首次或依赖变动时用 npm install
npm run dev            # http://localhost:5173
```

开发服务器的行为：

- HMR 覆盖 TSX 与 CSS；改 `src/index.css` 的 `@theme` 立即生效（v4 起配置即 CSS，不存在「改了配置要重启」的旧问题）。
- `StrictMode` 使开发期 effect 跑两遍。若发现「打开弹窗时某 effect 触发两次」，这是 StrictMode 的预期行为，不要为此加 `useRef` 守卫。

## 3. 命令表

| 命令 | 实际执行 | 用途 | 退出码含义 |
| --- | --- | --- | --- |
| `npm run dev` | `vite` | 开发服务器 | — |
| `npm run build` | `tsc -b && vite build` | 类型检查 + 生产构建 | 非 0 = 类型错误或构建失败 |
| `npm run preview` | `vite preview` | 预览 `dist/` | — |
| `npm run verify:data` | `node scripts/verify-styles.mjs` | 数据完整性 / 字体 / 对比度 | `1` = 有 error（warn 不置错） |
| `npm run verify:ui` | `node scripts/verify-ui.cjs` | 43 项浏览器断言 | `1` = 有断言失败；`2` = 脚本异常（找不到浏览器等） |
| `npm run verify` | `verify:data && build` | 提交前的默认关卡 | 任一失败即中断 |

**注意**：`verify` **不包含** `verify:ui`。原因是后者需要一个已启动的服务器与本地 Chromium，不适合作为无头环境下的默认关卡。发版前应手动跑一次。

## 4. 构建

### 4.1 两个阶段

```
tsc -b            → 走 tsconfig.json 的项目引用
                    ├─ tsconfig.app.json（src/**，strict + noUnusedLocals + noUnusedParameters + noFallthroughCasesInSwitch）
                    └─ tsconfig.node.json（仅 vite.config.ts）
                    产出：无（noEmit），只做类型检查；*.tsbuildinfo 记录增量状态（已 gitignore）

vite build        → Rolldown 打包 + Tailwind 扫描类名 + Lightning CSS 压缩
                    产出：dist/
```

### 4.2 实测产物（2026-11-12，35 条风格）

| 文件 | 原始 | gzip |
| --- | --- | --- |
| `dist/index.html` | 2.31 kB | 1.15 kB |
| `dist/assets/index-*.css` | 27.06 kB | 5.79 kB |
| `dist/assets/index-*.js` | 351.85 kB | 108.62 kB |

JS 体积主要来自 React 19 运行时 + 35 条提示词文本（约 120 kB 原始字符）。**每加一条风格约增加 3–4 kB** 未压缩体积。

### 4.3 路径与部署

`vite.config.ts` 设 `base: './'`，因此 `dist/index.html` 里引用的是相对路径：

- 可部署在域根（`https://host/`），也可部署在子路径（`https://host/gallery/`），无需改配置。
- 无 history 路由（只用查询参数），**刷新任意深链都命中同一个 `index.html`，不需要服务端 rewrite 规则**。

### 4.4 预览生产包

```bash
npm run build
npm run preview -- --host 127.0.0.1     # 默认 4173 端口
```

显式给 `--host 127.0.0.1` 的原因：`vite preview` 默认只监听 `localhost`，在某些 Windows 环境下解析为 `::1`，而 `verify:ui` 默认访问 `http://127.0.0.1:4173`，会出现「服务已起但连不上」。

## 5. 三层验证

### 5.1 第一层：类型

`tsc -b` 的严格项（`tsconfig.app.json`）：

| 选项 | 拦截的问题 |
| --- | --- |
| `strict` | 隐式 `any`、可能为 `null` 的访问 |
| `noUnusedLocals` | 声明未使用的变量（防止半成品改动混入） |
| `noUnusedParameters` | 未使用形参（约定：确需保留时加 `_` 前缀，见 `designMdFilename(_item)`） |
| `noFallthroughCasesInSwitch` | `switch` 穿透 —— 这对 `Preview` 的变体分派很关键 |
| `isolatedModules` + `moduleDetection: force` | 保证每个文件可独立转译（Rolldown 要求） |

### 5.2 第二层：数据（`verify:data`）

流程：用 esbuild 把 `src/data/styles.ts` 打成临时 ESM（`.tmp-styles.mjs`）→ 动态 `import` → 断言 → 删除临时文件。

| 检查组 | 检查内容 | 级别 |
| --- | --- | --- |
| §1 数据完整性 | `id` 非空且唯一；`nameZh/nameEn/category/summary/prompt` 非空；`category ∈ CATEGORIES`；`tags` 非空；`preview` 11 个必填键；`palette` 8 个键；变体名在枚举内；7 段标题齐全；无 `TODO/占位/待补充` | error |
| §1 体量 | 提示词去空白后 < 300 或 > 900 字符 | warn |
| §2 字体真实性 | `headingFont` / `bodyFont` 中每个非通用族名必须出现在 `index.html` 的 `family=` 里 | error |
| §3 对比度 | `text` / `textMuted` 对 `bg` 与 `surface` 的合成后对比度，取最小值 < 4.5:1 | warn |
| §4 分布 | 打印分类计数 | 信息 |

输出示例（当前基线）：

```
风格总数: 35
分类: 现代 / 极简 / 复古 / 工业 / 柔和 / 未来 / 艺术 / 国风 / 企业
分类分布: {"现代":6,"极简":3,"未来":4,"复古":8,"工业":3,"柔和":3,"艺术":4,"国风":1,"企业":3}
引用字体族: 27 个，全部已在 index.html 引入: true
--- 错误 --- 无
--- 警告 --- 无
```

对比度的计算细节值得知道：`surface` 若带 alpha，会先与 `bg` 合成；前景同理。也就是说**半透明色板不会被「看起来还行」蒙混过关**。

### 5.3 第三层：行为（`verify:ui`）

**前置条件**：已构建并启动预览服务（推荐 `npm run preview -- --host 127.0.0.1`），且本机存在 Chromium。

```bash
node scripts/verify-ui.cjs http://127.0.0.1:4173    # 参数缺省即该地址
```

脚本自行解析 `playwright-core`：先常规 `require`，失败则去 `~/.workbuddy/binaries/node/workspace/node_modules/playwright-core` 找。**它不在 `package.json` 里**，换机器可能需要手工准备。

**43 项断言分组**：

| 前缀 | 主题 | 覆盖点 |
| --- | --- | --- |
| `W7` | 站点元信息 | favicon 200、`og:title`/`og:description`/`theme-color` 存在 |
| `W2` / `W3` | 视觉与无障碍 | 半透明色块有 conic 棋盘格底衬；所有卡片预览 `aria-hidden` |
| `F1a`–`F1e` | 深链分享 | 分类 + 详情恢复；分享按钮反馈；URL 只用英文 slug；旧中文分类链接可读并规范化回写 |
| `S1a`–`S1c` | 焦点管理 | 初始聚焦在弹窗内、25 次 Tab 不逃逸；Esc 关闭；关闭后焦点归还触发按钮 |
| `F2a` / `F2b` | Markdown 导出 | 单条文件名 `style-<id>-YYYYMMDD.md` 且含「反模式禁令」；合集 35 篇 + 目录 |
| `F3a`–`F3h` | 收藏与最近 | `aria-pressed` 联动；写入 `style-gallery:favorites`；chip 置顶；筛选时 URL 纯净；最近上限 8、去重、最近在前；两种空态文案互不混淆 |
| `F4a`–`F4e` | 定制抽屉 | 预览 + 3 滑块 + 结果；密度 9 → `padding 12px`、实验度 9 → 错位 + 文本含 `9/10`；品牌名与 `#ff0000` 同时进预览与文本；关闭禁令段；复制反馈 |
| `F5a`–`F5k` | 对比模式 | 加入 / 移除 / 清空；第 4 款被拒 + `role=status` 提示且自动消失；同屏仅一个 dialog；3 份 Preview 并排；7 段横向对照；焦点陷阱；关闭后对比集保留 |
| `F9a`–`F9c` | DESIGN.md | 文件名 + 六章节；Color Palette 8 行 Token 且值与 `preview.palette` 一致；合集 35 篇 + 目录 |
| `REG1`–`REG3` | 回归 | 稀疏分类（≤3 张）下 sticky 恒钉顶且 URL 同步；`li` 均在 `ul` 内、`h2` 恰 1 个、`h3`/`h4` 均有；无控制台错误 |

**设计原则**（改 UI 时必须遵守）：

1. **断言不绑 Tailwind 类名**。锚点是 `aria-current="true"`、`aria-pressed`、`data-compare-row`、`data-swatch`、`role="status"`、`role="dialog"`。改配色或换工具类不会打断测试。
2. **断言不做全局计数假设**。除 `TOTAL_STYLES` 外，卡片数等一律用「> 0 且满足关系」而非固定数字。
3. **断言顺序敏感**：所有断言共享一个 page 与浏览器上下文，靠 `resetApp()` 清空 localStorage 后重载来隔离。插入新断言时注意它前后依赖的状态。

## 6. 排错手册

| 症状 | 最可能原因 | 处理 |
| --- | --- | --- |
| `verify:data` 报「找不到模块 esbuild」 | 依赖未装或 `esbuild` 被移除 | `npm ci`；不要删 `esbuild` devDependency（Vite 8 不再传递提供） |
| 命令返回退出码 127 | PATH 里的 node 目录已变更（托管环境常见） | 用 `node -v` 确认可用性，重新定位 node 目录 |
| `verify:ui` 报「未找到 playwright-core」 | 托管工作区路径变化或包被清理 | 在 `~/.workbuddy/binaries/node/workspace` 安装 `playwright-core`，或改脚本的候选路径 |
| `verify:ui` 报「未找到本地 chromium」 | `ms-playwright` 版本目录变化 | 更新 `CHROME_CANDIDATES` 中的版本号 |
| `verify:ui` 连接超时 | 服务只监听 `::1` | `npm run preview -- --host 127.0.0.1` |
| 开发环境颜色发灰 / 透明度失效 | Tailwind 4 在 dev 只输出 `color-mix()`，生产才由 Lightning CSS 补静态回退 | **看 `npm run build` 的产物判断是否真丢样式**，不要以 dev 为准 |
| 开发环境透明度全失效（连颜色都没了） | 浏览器低于 Chrome 111 / Safari 16.4 / Firefox 128 | 升级浏览器；这是 Tailwind 4 的硬门槛 |
| 抽屉文字出现彩色边缘 | `.suppress-subpixel-aa` 被删除（它的透明描边让文字走灰度抗锯齿） | 恢复该类；若抽屉已去掉进入动画，可删并重新核对观感 |
| 提交被钩子拦下 | 提交信息不符合 Conventional Commits 收窄版 | 按提示改 `<type>(<scope>): <描述>`；紧急情况 `--no-verify` |
| 构建通过但页面白屏 | `#root` 缺失或 JS 路径错（`base` 改动） | 检查 `index.html` 的 `#root` 与部署路径 |
| 收藏在隐私模式点了没反应 | `writeIds` 静默失败，无用户反馈 | 已知限制，见 07 §3 |

## 7. Git 约定与钩子

| 项 | 配置 | 说明 |
| --- | --- | --- |
| 钩子路径 | `.githooks/commit-msg`（`core.hooksPath` 已配） | 零依赖 sh 脚本 |
| 校验规则 | `^(feat\|fix\|style\|a11y\|perf\|refactor\|docs\|chore\|build\|ci\|test\|revert)(\(scope\))?!?: .+` | 冒号后必须有空格 |
| 放行 | `Merge *` / `Revert *` / `fixup!*` / `squash!*` / 空标题 | — |
| 模板 | `.gitmessage`（`commit.template` 已配） | 提交时自动带注释示例 |
| 完整规范 | `docs/Git提交规范.md` | scope 取值、正文与脚注格式 |

提交时机由人工决定；**除明确要求外，不要自动提交**。

## 8. 发版检查清单

```bash
npm ci
npm run verify                    # 数据 + 类型 + 构建
npm run preview -- --host 127.0.0.1 &
node scripts/verify-ui.cjs        # 43 项行为断言
```

外加人工确认：

- [ ] 新增 / 修改的风格在浅色、深色、半透明三类样张下都成立（`Preview` 的硬编码色值最容易出问题）
- [ ] `docs/code-wiki` 中受影响的小节已同步（尤其 02 字段表、05 耦合常量表）
- [ ] `index.html` 的 OG 描述仍与当前功能一致
