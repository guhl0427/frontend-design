# 01 · 架构总览

> 一句话结论：这是一个**编译期烘焙数据、运行期零网络请求**的单页静态应用；架构复杂度集中在「内容数据 + 预览渲染」这一对耦合上，而不在状态管理或路由上。

---

## 1. 架构定位

| 维度 | 形态 | 说明 |
| --- | --- | --- |
| 应用形态 | 静态 SPA，单入口 | `index.html` → `src/main.tsx` → `App` |
| 数据来源 | 编译期常量 | `src/data/styles.ts` 直接被打进 bundle，无 fetch |
| 状态边界 | 内存 + URL + localStorage 三层 | 见 §4 |
| 渲染方式 | 客户端全量渲染 | 无 SSR / SSG / 水合 |
| 服务端 | 无 | 无 API、无数据库、无鉴权 |
| 外部运行时依赖 | Google Fonts 一处 | `index.html` 的 `<link>`，失败时降级为系统字体 |

由此推导出两条硬性质：

1. **首屏之后不可能因网络失败而功能缺失**（字体除外，且字体缺失只影响观感不影响可用性）。
2. **所有用户态数据都在浏览器本地**，换设备 / 换浏览器即丢失，不存在账号概念。

## 3. 分层视图

依赖方向严格单向，**下层不知道上层的存在**。

```
┌──────────────────────────────────────────────────────────────┐
│ L5 容器层    App.tsx                                          │
│              编排状态、筛选、导出、模态互斥                        │
├──────────────────────────────────────────────────────────────┤
│ L4 组件层    StyleCard / PromptDetail / Customizer            │
│              CompareTray / CompareDialog / Preview            │
│              只通过 props 收发，不读全局态                        │
├──────────────────────────────────────────────────────────────┤
│ L3 Hook 层   useCopy / useFocusTrap / useLibrary              │
│              封装浏览器副作用（剪贴板、焦点、存储）                  │
├──────────────────────────────────────────────────────────────┤
│ L2 工具层    clipboard / viewState / promptSections           │
│              export / promptComposer                          │
│              纯函数优先；仅 export.downloadText 与              │
│              clipboard 触碰 DOM                                 │
├──────────────────────────────────────────────────────────────┤
│ L1 数据层    data/styles.ts · data/fonts.ts（常量）             │
│              types.ts（纯类型，无运行时代码）                     │
└──────────────────────────────────────────────────────────────┘
```

**约束**：L4/L5 不直接操作 `localStorage` 或 `history`，一律经 L3/L2；L2 不 import L3；L1 不 import 任何上层模块。

## 4. 状态模型（三层，各管一件事）

### 4.1 React 内存态 —— 只在 `App.tsx`

| 状态 | 类型 | 初始值来源 | 作用 |
| --- | --- | --- | --- |
| `activeFilter` | `string` | `readViewState().category`，非法值回落 `'全部'` | 当前筛选：`'全部'` / 分类名 / `'__favorites__'` / `'__recent__'` |
| `keyword` | `string` | URL `?q=` | 搜索关键词，实时过滤 |
| `selected` | `StyleItem \| null` | URL `?style=` | 详情弹窗目标 |
| `customizing` | `StyleItem \| null` | `null` | 定制抽屉目标 |
| `compareIds` | `string[]` | `[]` | 对比集，上限 3，存 id 而非对象 |
| `comparing` | `boolean` | `false` | 对比视图开关 |
| `notice` | `string \| null` | `null` | 轻提示（对比集上限），2600ms 自动消失 |

组件内部的局部状态只有三类，且都不需要外部知晓：`useCopy` 的 `copied`、`Customizer` 的 `options` 与入场动画 `entered`。

### 4.2 URL —— 只存「可分享的视图状态」

`?cat=<英文 slug>&q=<关键词>&style=<风格 id>`，写回用 `history.replaceState`（不污染后退栈），省略默认值以保持链接干净。

| 数据 | 是否入 URL | 原因 |
| --- | --- | --- |
| 分类 / 关键词 / 当前详情 | 是 | 分享后对方应看到同一屏 |
| 收藏 / 最近浏览 | **否** | 本地数据，写进链接会让接收者看到空列表 |
| 对比集、定制参数 | 否 | 瞬时操作态，无分享价值 |

`App.tsx` 为此显式做了过滤：当筛选是 `__favorites__` / `__recent__` 时，回写 `DEFAULT_VIEW.category` 而非该哨兵值（`App.tsx:102-109`）。

### 4.3 localStorage —— 只存跨会话的私人数据

| 键 | 值 | 上限 | 语义 |
| --- | --- | --- | --- |
| `style-gallery:favorites` | `string[]`（id） | 无限 | 最近收藏在前 |
| `style-gallery:recent` | `string[]`（id） | 8 | 去重，最近在前 |

两端读写均容错：隐私模式 / 非法 JSON / 配额不足一律降级（读返回 `[]`，写静默失败）。跨标签页通过 `storage` 事件同步。

### 4.4 三层之间的不变量

1. **URL 永远是内存态的下游**：内存态变化 → 写 URL；URL 只在首屏被读取一次，之后不再作为数据源。
2. **id 是唯一的跨层引用**：对比集与本地库都存 `string[]`，渲染前用 `resolveById` 映射，已删除的 id 自动被丢弃（不会崩）。
3. **模态互斥**：`selected` / `customizing` / `comparing` 三者同屏最多一个为真，且切换由 `App` 的处理函数保证（打开定制前先 `setSelected(null)`，打开对比前同理）。

## 5. 数据流

### 5.1 从常量到像素

```
STYLES（常量数组，35 项）
   │
   ├─→ filterStyles(STYLES, activeFilter, keyword, favorites, recent)
   │        │  ① 选基底：分类过滤 / 收藏 / 最近
   │        │  ② 关键词：nameZh+nameEn+category+summary+tags 拼接后 includes
   │        └─→ visibleStyles ──→ StyleCard[] ──→ Preview(item.preview)
   │                                  │
   │                                  └─ 编号 = STYLES.indexOf(item) + 1
   │
   ├─→ resolveById(compareIds) ──→ compareItems ──→ CompareTray / CompareDialog
   │
   └─→ 单条 item ──→ PromptDetail（正文 / 色板 / 字体）
                 ├─→ composePrompt(item, options)  → Customizer 的文本结果
                 └─→ derivePreview(item, options)  → Customizer 的实时预览
```

关键点：**筛选只做一次记忆化派生**（`useMemo` 依赖 `[activeFilter, keyword, favorites, recent]`），不做「先改数组再渲染」的多段 setState，因此不存在中间态不一致。

### 5.2 三个导出通道

| 通道 | 入口 | 产物 |
| --- | --- | --- |
| 单条 Markdown | `PromptDetail` 的「下载」 | `style-<id>-YYYYMMDD.md` |
| 合集 Markdown | `App` 的「导出 N 条 .md」 | `style-prompts-collection-YYYYMMDD.md`（含目录，正文标题降一级） |
| DESIGN.md | `PromptDetail` / `App` | 单条固定名 `DESIGN.md`；合集 `design-md-collection-YYYYMMDD.md` |

三者共用 `splitPrompt` 或直接拼装 `item.prompt`，均通过 `downloadText` 触发 Blob 下载，无服务端参与。

## 6. 双轨样式系统：外壳用令牌，预览用内联样式

这是本项目最容易被误改的地方，必须区分两套样式来源。

| | 外壳（页面框架、卡片容器、弹窗、按钮） | 预览（`Preview.tsx` 渲染的样张） |
| --- | --- | --- |
| 来源 | Tailwind 工具类 + `@theme` 令牌 | React `style` 内联对象，值来自 `item.preview` |
| 令牌 | `src/index.css` 的 `@theme` 是唯一来源 | 不使用外壳令牌，只用风格自身的 `palette` |
| 圆角 | 全站 2px（`--radius-sm~3xl` 被覆盖） | 由 `preview.radius` 决定，可为胶囊或 0 |
| 颜色 | 石墨 + 琥珀（面积预算 < 2%） | 任意，彩色全部归预览所有 |
| 改动风险 | 改令牌即全站生效 | 改 `Preview` 会影响全部 35 条样张 |

**判断改动是否跑偏的一句话标准**：外壳只给石墨细线、等宽编号和刻度，彩色全部归预览所有。若新改动让外壳出现大面积彩色，即偏离既定视觉方向。

另一个必须遵守的细节：**外壳标记不许叠在预览上**。预览样张底色由 35 套色板决定，任何叠加色都无法同时成立；星标曾用绝对定位压在样张右上角，在浅色样张上变成脏块，现已移到元信息行。

## 7. 首屏渲染时序

```
1. index.html 解析，Google Fonts 并行加载（display=swap，不阻塞）
2. main.tsx 执行 → createRoot(#root).render(<App/>)（StrictMode 下开发期 effect 跑两次）
3. App 首次渲染
   a. readViewState()：同步解析 window.location.search          ← 只此一次
   b. useState 初始化：activeFilter / keyword / selected 直接取 URL 值
   c. useLibrary 初始化：同步读 localStorage（避免「先空列表再回填」的闪烁）
   d. useMemo 计算 visibleStyles
4. 首次提交（paint）—— 此时分类、关键词、详情弹窗均已是正确状态
5. useEffect 写回 URL（与步骤 3a 读到的值相同 → replaceState 不产生可见变化）
6. 字体到位后文字重排（无布局抖动防护，靠 font-display: swap 的本性）
```

**设计意图**：所有「能同步读到的初始状态」都在 `useState` 初始化函数里同步读取，不放到 `useEffect` 里回填。这避免了深链打开时先闪现「全部分类 + 无弹窗」再跳到目标状态的错帧。

## 8. 关键设计决策与代价

| 决策 | 收益 | 代价 / 风险 |
| --- | --- | --- |
| 数据编译进 bundle | 零请求、零加载态、可离线 | 加内容必须重新构建部署；bundle 随条数线性增长（当前 JS 351 kB） |
| 预览用内联样式而非 CSS 类 | 每条风格的规则完全数据驱动，无需为 35 条写 35 套 CSS | 无法用媒体查询；预览不能响应容器宽度；样式无法被浏览器缓存复用 |
| 对比集 / 本地库存 id 不存对象 | 存储小、天然去重、数据结构变更不失效 | 每次渲染要做 `find` 映射（35 条规模下可忽略） |
| 分类中文名 + URL 英文 slug | 界面中文友好，链接 ASCII 可读、不被二次转义 | 多一张映射表，新增分类要同步 4 处（见 05 §5） |
| 无路由库，手写 URL 同步 | 零依赖、行为可预测 | 只有 `style` / `cat` / `q` 三个参数；扩展参数需手改 `viewState.ts` |
| 断言用裸脚本不引入 runner | 零依赖，可直接查真实 DOM | 无并行、无 watch、断言之间共享页面状态，顺序敏感 |
| 一个文件承载全部数据（2191 行） | 内容集中在单一可 diff 的结构里 | 文件大；合并冲突概率高；IDE 内导航靠 `id` 搜索 |

## 9. 部署形态

- 产物为 `dist/`（`index.html` + `assets/index-[hash].{js,css}` + `favicon.svg`）。
- `vite.config.ts` 设 `base: './'`，因此可放在任意子路径（如 `https://host/gallery/`）而无需改配置。
- 无 history 路由，刷新任意深链都命中同一个 `index.html`，**不需要服务端 rewrite 规则**。
- 待补：`og:image`（1200×630 PNG）与线上绝对 `og:url`，当前只有文本类 OG 标签。
